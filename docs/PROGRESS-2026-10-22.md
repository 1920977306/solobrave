### 3. 真根因（本机复现，不是推测）

`79999` **超出 TCP 端口上限 65535**：

| 端口 | urllib 行为 |
|---|---|
| 79999 / 65536 | `gaierror [Errno 8] nodename nor servname provided, or not known` ← **与原始告警逐字一致** |
| 65535 / 9999 | `[Errno 61] Connection refused` |
| 7188 | `200` |

⇒ 原始告警里的「DNS 解析失败」**不是驾驶舱连不上**，是**探针写了个非法端口**（7188 少打一位）。
告警文案把「配置写错」说成了「驾驶舱异常」——老大被误导的地方正在这里。

### 4. 处置：把体检搬回本机（真值版探针）

`~/Developer/solobrave-ops/healthcheck.py` 新增 `cockpit_probe()`，接进已有 watchdog（launchd 每 120s）：

- 端口 `7188`（可用 `SB_COCKPIT_PORT` 覆盖），检查项沿用原名：`keys_ok` / `reach` / `http_200` / `form_anon_ok`
- `http_200` **带 k** 打 `/api/cockpit`（不带 k 必然 403 → 鉴权问题 ≠ 服务故障）
- **端口闸门**：越界直接判「端口非法」并拦下，不再伪装成网络故障
- **k 绝不进日志、绝不进告警文案**（k 等同访问密码）
- 告警走 healthcheck **既有通道**（飞书 webhook / Bark / 系统通知），30 分钟节流，与主服务/网关故障同一通道
- 回滚点：`healthcheck.py.bak-20261022-175319`

| 场景 | 结果 |
|---|---|

| 端口 79999 | `reach/http_200/form_anon_ok=False`，detail = **「端口非法：79999 超出 TCP 上限 65535」** |

### 4. 交互层新坑（连废 8 个探针才定位）

块菜单的二级飞层**必须用带轨迹的鼠标移动**才展开：
`mouse.move(x-60,y)` → `mouse.move(x,y,steps=12)`。
单点瞬移 / `locator.hover()` / JS `.click()` / `click(force=True)` 全部不触发；
症状极具误导性（面板永远 `offsetParent===null`，报错像「面板没渲染」）。
且 DOM 里有多份同名隐藏副本 ⇒ **一律按可见筛，别用 `.first`**。

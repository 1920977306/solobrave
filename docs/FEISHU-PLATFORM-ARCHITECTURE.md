# 飞书助理平台 · 架构重构提案（2026-11-01，老大指令）

> 触发：老大三连问——①飞书功能在系统上显示不出来 ②达人想升级做团长没有路径
> ③admin 只是客户视角没有总台。要求：把飞书功能立成独立项目，三类客户
> （商务/达人/商家）× 三个 AI 角色（商务/达人/商家助理），角色可见、可控、可评估。
> 本文档第一部分全部来自木木租户 68 条真实达人消息（拉取时间 2026-11-01 18:2x）。

---

## 一、达人真实需求（实证，不是猜的）

数据源：mumu 租户（豆鲨包 62224890070）与达人的全部飞书消息，10-26 ~ 10-31，达人侧 68 条。

### 1.1 需求分布（按消息归类）

| 需求类 | 条数 | 典型原话 |
|---|---|---|
| **账号分析（自己+对标）** | ~14 | 「豆鲨包 抖音号：62224890070 帮我分析这个账号」「抖音号：20915357798 帮我分析这个达人」 |
| **选品/商品判断** | ~12 | 「3813500959800295750 是投流品 这个可以带吗」「给我推荐几个适合我的产品呗」「发绳类的商品 可以再给我推荐几个嘛」 |
| **成长/对标/定位** | ~8 | 「帮我找几个豆鲨包账号的对标呗 我想提升一下账号」「我的目标人群是啥样的 客单价控制在多少」「我可以带鞋靴类目的嘛」 |
| **视频内容拆解** | ~7 | 「帮我分析一下这个视频」「把这两个视频做一下对比 包括前三秒的对比」 |
| **复盘（自己历史数据）** | ~4 | 「那我过往带货的品类 有哪些是不错的」「我出单的卖得好的品 你知道是啥吗」 |
| 图片识别（截图给上下文） | ~6 | 带货品类截图、出单列表截图 |

### 1.2 ★ 最强的信号：翻车点 = 未满足需求

| 达人原话 | 暴露的问题 |
|---|---|
| 「我发给你的是两个视频链接呢 **怎么没有两个视频对比**」 | **多对象并行分析缺失**——达人同时丢 2 个视频链接，bot 只分析了一个 |
| 「**不是**豆鲨包」「**我说**这个」 | **上下文承接失败**——连续发的多个对象（账号/商品/视频），bot 处理错对象 |
| 「你分析啊」（发了截图没下文） | 图片消息处理后**响应缺失/太慢**，达人以为没收到 |
| 「行动建议**没听懂**」 | 输出太抽象，缺**一步一步可执行**的建议 |

### 1.3 结论

1. 达人的真实工作流是**多对象并行**：自己的号 + N 个对标 + M 个商品 + K 个视频，同时推进。现在的 bot 是单轮单对象架构——这是第一优先级缺口。
2. 「成长顾问」需求（对标、定位、下一步做什么）比「选品工具」更稀缺——达人反复问的是**"我该怎么办"**，不是"这个品能不能带"。
3. 每次翻车达人都在**教 AI**（纠正已入 talent_feedback 知识库），这正是角色模板要消化的东西——角色好不好，看翻车率就知道。

## 二、现状诊断：五个结构性缺口

| # | 老大的话 | 根因 |
|---|---|---|
| 1 | 飞书功能在系统无法显示 | `bot_tenants`（3 个飞书应用实例）只活在 bot 自己的 8092 admin 里，server 主系统**没有任何页面**能看到它们 |
| 2 | 达人想做团长没路径 | 没有「客户→代理→平台」的层级概念，租户之间是平行的，没有归属关系 |
| 3 | 没有管理后台/权限控制 | server 只有一个 `admin` 布尔位（客户视角的"我的设置"），没有**运营总控台**（跨租户视角） |
| 4 | 角色不可见不可控 | 角色基建其实**已有一半**：`config.VALID_ROLES`（daren/commerce/merchant）+ `personas/*.md` 模板 + 按角色注入 persona——但**没有任何界面展示**「木木是达人助理，它的模板是什么、训练沉淀了多少条」 |
| 5 | 角色好坏没法评估 | 聊天内容不落库（只有计数），翻车/纠正没有度量——老大说「做的是不是好的，是不是适合客户的」现在**答不了** |

## 三、目标架构：飞书助理平台（Feishu Assistant Platform）

### 3.1 三个核心概念（把已有东西正名）

```
客户(Customer)          飞书应用实例(Tenant)         AI 角色(Role)
─────────────           ───────────────────          ──────────────
达人/商务/商家    →     一个客户一个飞书自建应用  →    角色模板(personas/*.md)
(客户群体，              (bot_tenants 一行，            + 能力白名单(能调哪些
 可按层级归属)            凭证/绑定/积分都在这)           API) + 训练沉淀(纠正榜)
```

- **客户 ≠ 租户 ≠ 角色**：一个客户（达人豆鲨包）= 一个租户（mumu 应用）= 一个角色实例
  （达人助理）。现在三者 1:1:1 混在一起，所以"显示飞书功能"无处可挂。
- **角色是产品**：商务助理/达人助理是三个 SKU，每个 SKU = 模板 + 能力集 + 定价（积分单价）。
  商家助理已预留（ROLE_MERCHANT），暂不上线，但管理界面里要**看得见"未启用"**。

### 3.2 权限模型（解决"达人升团长"）

```
平台超管(老大, server admin)
   └─ 代理/团长(Agent)：可管理自己名下的达人租户
         └─ 达人/商务客户：只能用自己的助理
```

- `bot_tenants` 加两列：`parent_customer`（归属哪个代理）、`customer_plan`（角色 SKU）。
- **达人升团长 = 一条数据变更**：开个代理账号 → 把她名下的租户挂过去 → 她获得代理后台
  （看自己名下达人的用量/帮充值/看报告）。**不需要她懂技术，也不动飞书应用。**
- server 侧复用现有 `_authenticate` 的 `is_admin / is_tenant_admin` 两级——代理就是
  tenant_admin 的泛化。

### 3.3 ★ 运营总控台（Feishu Console）——本期要建的

挂在现有 admin 里的一个新页面（跟 LLM 消耗面板同级入口），六个区块：

| 区块 | 内容 | 数据来源（全部已存在） |
|---|---|---|
| **租户总览** | 每个飞书应用一张卡：角色、绑定抖音号、WS 在线、余额、近30天消耗 | `/admin/api/state` + `/admin/api/credits`（今天刚建的代理通道） |
| **角色管理** | 三个角色 SKU 卡：模板版本、训练沉淀条数（纠正榜）、启用状态（商家助理显示"未启用"） | `personas/*.md` + talent_feedback 知识库 |
| **聊天审计** | 每个租户最近会话流（消息落库后） | 新表 `bot_chat_messages`（见 P0） |
| **积分运营** | 飞书 AI 区块（今天已上线）+ 批量充值 | 已有 |
| **翻车率看板** | 每个角色的纠正率、拒答率、无响应率——**"角色好不好"的量化答案** | 聊天审计表 + talent_feedback |
| **开通/关停** | 新建租户（代客创建飞书应用向导）、关停、角色切换 | add-tenant CLI → 页面上化 |

### 3.4 P0/P1/P2 分期

**P0（聊天落库——一切的地基，1~2 天）**
现在聊天文本**哪里都不存**（日志只有元数据），所以"角色好不好""达人需求是什么"永远
只能手工拉。做 `bot_chat_messages` 表：消息入库（含图片 key），handler 写、审计页读。
→ 这一步做完，翻车率/需求分析全部自动化。

**P1（控制台骨架，2~3 天）**
server 新页面「飞书助理」：租户总览 + 角色管理 + 积分运营三区（数据全走今天建好的
8092 代理模式，不新开 bot 写接口）。

**P2（多对象并行 + 代理层级，1 周）**
- 会话内对象栈：达人连发的多个链接/ID 依次入队分析，支持"两个视频对比"这类
  跨对象指令（翻车最狠的坑）。
- 代理层级：`parent_customer` + 代理后台（只读视角先）。
- 角色 SKU 定价：不同角色不同积分单价。

## 四、先答老大的三个问题（一句话版）

1. **飞书功能显示不出来** → P1 控制台，租户/角色/积分一屏管理（数据通路今天已打通）。
2. **达人升团长** → 代理层级模型，达人→代理是一次数据变更 + 一个只读后台，不动飞书应用。
3. **权限没有控制的地方** → 三级权限（超管/代理/客户）落 `bot_tenants` 两列 + server
   现有 admin/tenant_admin 鉴权泛化。

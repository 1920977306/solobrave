# 达人产品架构：飞书机器人 × 网页驾驶舱

> 更新：2026-10-19 · 一句话：**代码挨着住，各过各的日子，共用同一份数据。**

## 总览

```
                        ┌─────────────────────────────────────────────┐
                        │              solobrave-prod（一个 git 仓库） │
                        │                                             │
   达人（飞书聊天）      │   daren_bot/                  daren_cockpit/ │
        │               │   ├─ ws_manager   ← 长连接     ├─ server.py  │
        ▼               │   ├─ worker       ← 采集执行   └─ index.html │
   飞书开放平台 ──ws──▶ │   ├─ bitable_sync ← 写表格                  │
        │               │   ├─ reflow       ← 数据回流                │
        │               │   └─ data/daren-bot/daren_bot.db            │
        │               │            （租户绑定：抖音号/表格ID/积分）    │
        │               └─────────────────────────────────────────────┘
        │                     ▲读绑定                ▲读绑定
        │                     │                     │
        ▼                     │                     ▼
   多维表格（飞书） ◀──────────┘              ┌─ 浏览器/手机 ─┐
   ├─ 租户 profile/log/products 表            │ 达人经营驾驶舱 │
   └─ 样板库合作机会表                          └───────────────┘
```

## 两个进程，三条铁律

| | daren_bot（机器人） | daren_cockpit（驾驶舱） |
|---|---|---|
| 职责 | 收飞书消息 → 采集 → 推结论 | HTTP 页面，达人自己点开看 |
| 入口 | ws_manager 长连接 | `python3 server.py --port 7100` |
| 对 daren_bot.db | 读写 | **只读**（拿绑定关系） |
| 对 solobrave.db | 读写 | **只读**（达人档案/选品匹配） |
| 对多维表格 | 写（采集结果/选品结论） | 读（lark-cli，120s 缓存） |

1. **进程独立**：机器人挂了页面照样开（数据停更而已）；页面挂了不影响收消息。
2. **单向依赖**：驾驶舱只读，永不写机器人的库；机器人代码零改动。
3. **数据同一份，不分家**：机器人在聊天窗把结论**推**给达人，驾驶舱让达人**自己看**全局——同一产品的两面。拆仓库意味着两套同步，内测期不做。

## 数据流向

```
达人发抖音号 ──▶ 机器人采集百应 ──▶ 写多维表格 + solobrave.db
                                        │
                                        ▼
                     驾驶舱 server.py 聚合三层（租户DB绑定 → solobrave只读 → lark-cli读表格）
                                        │
                                        ▼
                     index.html 微信风渲染 + echarts（粉丝趋势/结论环/互动条）
```

## 为什么不合进一个进程

机器人 ws 是常驻长连接，再背 HTTP 等于一挂全挂；分开跑各自崩溃隔离、日志分开好排查。

## 三层分工（2026-10-20 钉死，防跨对话重复建设）

| 层 | 载体 | 负责方 | 干什么 |
|---|---|---|---|
| 触达层 | 飞书机器人对话 | daren_bot（另一对话） | 周报/报告/问答推送、百应采集、积分——达人零操作收结论 |
| 工作台层 | 7188 网页 `daren_cockpit` | 本对话 | 三身份入口、运营总览（/api/roster）、合作管道可写回、规模化扩展 |
| 档案层 | ~~租户多维表格（应用身份自动建）~~ **已换代：mini 做的达人经营驾驶舱（新功能）** | ~~daren_bot `bitable_sync`~~（2026-10-27 老大拍板废弃，调用已停用，模块保留备查） | 采集结果双写账本，机器人写、网页读 |

**铁律：**
1. 工作台只做在网页，不在飞书重做（天花板见 DAREN-WORKBENCH-COMPARISON.md：仪表盘 API 逐租户审批/区块不可改/布局不可控）
2. 机器人推送卡片统一带达人专属工作台链接 `http://192.168.1.25:7188/?t=<tenant_key>`——飞书是门，网页是工作台
3. 飞书原生能力只补不重叠的增量：多维表格自动化（商品更新→通知达人）、插件 SDK 小组件（远期）

## 部署

- 机器人 + 采集：跑在运营 Mac（本机），随 daren_bot 现有自启。
- 驾驶舱：`daren_cockpit/server.py`，内网服务器 192.168.1.25 systemd 常驻（见 `docs/DAREN-COCKPIT-DEPLOY.md`）。
- ⚠️ 驾驶舱依赖的三样——`daren_bot.db`、`solobrave.db`、lark-cli 身份——都是 Mac 侧的，服务器部署时必须同步数据/改数据源，详见部署文档。

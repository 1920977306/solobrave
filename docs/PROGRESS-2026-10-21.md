## 一、问答链复活：订阅制额度 ≠ 开放平台余额

### 根因

老大一句「**充值？我买的是 code 啊**」揭出真相：老大买的是 **MiniMax Code 订阅（M Plan）**，
额度**绑定在客户端凭据上，根本不走开放平台余额**。原降级链三把 key 全灭：

| key | 端点 | 额度从哪扣 | 原状态 |
|---|---|---|---|
| `sk-api-…` 开放平台 | `api.minimaxi.com/v1` | 开放平台余额 | ❌ 402 余额 0 |
| `sk-kimi-…` | `api.kimi.com/coding/v1` | Kimi 月度额度 | ❌ 429 |
| `mmoat_…` Code OAuth | `agent.minimax.cn/…/llm/v1` | 客户端自持凭据 | ⚠️ 能用但 30 分钟一轮换 |
| `sk-cp-…` **套餐 key** | `api.minimax.cn/anthropic/v1` | **订阅套餐** | ✅ **唯一有额度** |

⚠️ 三者是**三本独立的账**。看到其中一把报 402/401，**不代表**另两把也没额度。

### 落地

`daren_bot/executors.py` 降级链从「4 元组」升级为「带 `protocol` / `auth` 字段的环结构」，
环序按**凭据稳定性**排（老大拍板「套餐优先」）：

| 环 | 协议 | 凭据 | 说明 |
|---|---|---|---|
| 0 | Anthropic | `.env` `MINIMAX_CP_API_KEY` | 长期凭据，主用 |
| 1 | Anthropic | Code OAuth token | 30 分钟轮换，备份 |
| 2 | OpenAI | 套餐 key | 协议冗余 |
| 3/4/5 | OpenAI | kimi / 开放平台 key | 目前全灭，保留 |

- **协议不能混用**：`agent.minimax.cn` 的 `/chat/completions` 返 503，只有 `/messages` 通
- **鉴权头显式化**：`ring['auth']` 声明 `x-api-key` / `bearer`，两种实测都通
- **推理标签剥离**：M3 走 OpenAI 协议时 content 开头是 `<think>…`，不剥会给用户看一堆英文思考过程
- **命中日志必打**：`[fallback] 命中环N protocol=… model=… base=…` —— 否则「静默降级到 kimi」看不出来
- **逐环降级已逐环验证**：环0挂→落环1；环0+1挂→落环2；全挂→错误信息逐环列出真实原因

## 九、招商减负 + 商品展示改版（老大 18:41 新需求，本批）

### 需求原文

> 驾驶舱里的招商合作填表，商家只会提供商品链接 / 商品图片 / 其他达人带过的商品 / 一段话描述，
> 不会填那么多空，商家会嫌麻烦；工作台商品一多就一直往下划，要「今天的商品推荐」式呈现；
> 需要 AI 能识别商品链接、能看到商品数据。

### 落地

| 需求 | 做法 | 验证 |
|---|---|---|
| ① 招商填表减负 | 新建 `/apply` 极简页：2 必填（品牌/联系方式）+ 3 选一（链接/图片/描述），AI 自动补商品字段 | 负向 5/5 拒绝；描述路径实测抽出类目「休闲零食」 |
| ② 商品展示优化 | 服务端返回全量 + `is_today`；前端「今日推荐」网格 + 换一批 + 「更多推荐」折叠；合作机会区同样收敛 | Playwright 实测：换一批生效、第 1/2→2/2 批、折叠展开 3 行、0 JS 错误 |
| ③ AI 识别商品链接/看商品数据 | `collect_product_by_url()` 抽成公共函数；vision 链加套餐 key 兜底 | 图片路径 3.8s 抽出 name/price/佣金/销量/类目；链接路径代码就绪，**但采集器登录态已过期** |

### 关键决策

- **解析必须异步**：链接采集走团长端浏览器（全局单例、1-2 分钟）→ 同步等会让商家干等。
  提交即返回编号 `AP-XXXXXX`，后台线程解析完回填。
- **只丢不造**：解析不出来的字段留空 + `status='partial'`，绝不编商品信息。
- **管道复用**：解析结果同步回飞书合作机会表 → 运营的「待评估→有意向/已合作」流转和
  `coop_notify` 主动推送逻辑**一行不用改**。
- **商家提示区分「谁的问题」**：链接识别失败九成是采集器登录态过期，
  提示写「我们这边的采集账号需要重新登录」，不让商家背锅。

### 三个被实测抓出来的坑

1. **日志成哑弹**：`server.py` 没调 `logging.basicConfig()` → 提交解析失败时日志一行都没有，
   表现成「功能静默不工作」。已在 `main()` 显式开 INFO。
2. **record_id 路径不固定**：创建响应在 `data.record.record_id_list[0]`，
   更新响应压根没 id → 多种路径都试 + 取不到就**回查**（否则「同步成功但拿不到 id」= 静默失败）。
3. **`grid-template-columns:1fr` 撑破布局**：手机 420px 视口横向溢出 22px →
   改 `repeat(2,minmax(0,1fr))` + 长文本 `overflow-wrap:anywhere`。
   另：**inline `onclick` 只能查全局作用域**，函数写在 `render()` 里 = 点了没反应。

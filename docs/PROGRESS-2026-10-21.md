## 一、问答链复活：订阅制额度 ≠ 开放平台余额

### 根因

老大一句「**充值？我买的是 code 啊**」揭出真相：老大买的是 **MiniMax Code 订阅（M Plan）**，
额度**绑定在客户端凭据上，根本不走开放平台余额**。原降级链三把 key 全灭：

| key | 端点 | 额度从哪扣 | 原状态 |
|---|---|---|---|
| `sk-api-…` 开放平台 | `api.minimaxi.com/v1` | 开放平台余额 | ❌ 402 余额 0 |
| `sk-kimi-…` | `api.kimi.com/coding/v1` | Kimi 月度额度 | ❌ 429 |
| `mmoat_…` Code OAuth | `agent.minimax.cn/…/llm/v1` | 客户端自持凭据 | ⚠️ 能用但 30 分钟一轮换 |
| `sk-cp-…` **套餐 key** | `api.minimax.cn/anthropic/v1` | **订阅套餐** | ✅ **唯一有额度** |

⚠️ 三者是**三本独立的账**。看到其中一把报 402/401，**不代表**另两把也没额度。

### 落地

`daren_bot/executors.py` 降级链从「4 元组」升级为「带 `protocol` / `auth` 字段的环结构」，
环序按**凭据稳定性**排（老大拍板「套餐优先」）：

| 环 | 协议 | 凭据 | 说明 |
|---|---|---|---|
| 0 | Anthropic | `.env` `MINIMAX_CP_API_KEY` | 长期凭据，主用 |
| 1 | Anthropic | Code OAuth token | 30 分钟轮换，备份 |
| 2 | OpenAI | 套餐 key | 协议冗余 |
| 3/4/5 | OpenAI | kimi / 开放平台 key | 目前全灭，保留 |

- **协议不能混用**：`agent.minimax.cn` 的 `/chat/completions` 返 503，只有 `/messages` 通
- **鉴权头显式化**：`ring['auth']` 声明 `x-api-key` / `bearer`，两种实测都通
- **推理标签剥离**：M3 走 OpenAI 协议时 content 开头是 `<think>…`，不剥会给用户看一堆英文思考过程
- **命中日志必打**：`[fallback] 命中环N protocol=… model=… base=…` —— 否则「静默降级到 kimi」看不出来
- **逐环降级已逐环验证**：环0挂→落环1；环0+1挂→落环2；全挂→错误信息逐环列出真实原因

老大 10-20 问「我怎么打开驾驶舱」→ 机器人答不上来（Kimi 额度耗尽）；

改之前 `grep 7188|驾驶舱|sczlgyl daren_bot/*.py` → **0 处**。

### 落地

- 新增 `daren_bot/cockpit_link.py` —— 专属链接的**唯一来源**，不在各处散落拼串
- 消息含「驾驶舱/工作台/后台/看板」→ 直接回该达人专属链接，**零成本**（纯导航不是分析）
- 达人把链接发回来 → 回入口（**不再被当商品链接扣 20 分**）
- 报告卡 / 问答卡 / 周报看板长图页脚 → 统一带同一条链接
- 主语是抖音/字节/官方 → **不劫持**，那是问抖音官方产品

### 安全

- 链接形态 `https://daren.sczlgyl.com/?t=<tenant>&k=<专属k>`（一人一链）
- ⚠️ **k 等同于访问密码**：日志只记 `tenant_key`、**不打 k**；只发给达人本人
- 落地页 `/` 只返回静态外壳（**无任何租户数据**），数据在 `/api/cockpit` 校验 k：
  正确 k → 200 / 错误 k → 403 / 裸 `?t=` → 403

**触达层**的核心增量：不等达人来问，主动把匹配的合作机会推给合适的达人。

### 流程

```
读飞书「合作机会」表（lark-cli --as user + 120s 缓存，复用 7188 侧 lark_records）
  → 状态在「有意向/已合作」才处理 → 按合作类目匹配达人 → 灰度过滤
  → 去重（record_id+tenant_key）+ 频控（同一达人每周 ≤2 条）→ 推文本卡片
```

### 与工单草稿的三处口径收敛（按现状落地）

1. 合作机会表**没有「商品名」字段**（实际只有 品牌/商家 / 提交时间 / 合作类目 / 联系方式 /
   联系人 / 预算佣金 / 状态 / 合作说明）→ 匹配按**合作类目**走。
2. 触发状态收敛为「有意向 / 已合作」：「待评估」推给达人是打扰 + 可能推错；
   运营把新记录直接录成「有意向」时同样满足判据 → **一条条件覆盖两种触发**。
3. 达人链接用**公网** `https://daren.sczlgyl.com/?t=&k=`（工单草稿写的是内网
   `192.168.1.25:7188`，写于 10-20 当时公网还没通）。

### 匹配的两条路径

| 路径 | 链路 | 理由来源 |
|---|---|---|
| A 商品桥接 | 类目 → products → product_talent_match → 达人 | **现成的** `match_reason` |
| B 类目直配 | 类目 → talents.main_category → 达人 | 基于真数据生成 |

⚠️ **只丢不造**：匹配不到 → 不推（实测「休闲零食」在现有达人库 0 命中 → 诚实地不推）。

### 硬要求落实

① 去重+频控 → `bot_coop_push_log` 表（唯一索引 + 周计数）
② 灰度 → `COOP_GRAY_TENANTS`（默认 daren_boss + daren_test2）
③ 推送 → `ws.get_sender(tk)`（按租户自己的凭证）
④ 读表 → 复用 `daren_cockpit.server.lark_records`

## 子项清单（5 项）

### 批注①-1 侧栏员工项补全（角色后缀 + dot 三色）
- 位置：`renderSideFor` messages 分支员工项渲染 + `.sb2-side--module-messages` 作用域 CSS
- 改法：item name 后追加 `<span class="sb2-side-item-role">· 角色</span>`（micro 灰 t3 token）；dot 按员工状态三色（online 绿 / busy 橙 / offline 灰，颜色用现有 token）
- 验收：探针抽 3 个员工项，角色文本在、dot 颜色与状态一致；项目组群聊 items 不受影响

### 批注②-1 顶栏头像 28 → 32
- token：`--sb2-chat-topbar-avatar-size: 28px → 32px`（fontSize 保持 12px）

### 批注②-2 顶栏名字 600 → 400
- CSS：`.sb2-chat-topbar-name` font-weight 600 → 400

### 批注③-3 气泡布局还原（padding / 圆角 / 行高）
- `.sb2-chat-bubble` padding `10px 14px → 16px 24px`
- border-radius `14px 14px 14px 4px → 14px`（四角对称，跟原型圆角卡片；左右气泡同改）
- line-height 对齐 22.4px（用 token 或 1.6 乘数，**禁用无单位 px 简写坑**：`11px/15.4` 那种写法会乘数化，见妍妍学习清单）
- 验收：探针 computed diff=0（对 4 项属性）

### 批注③-4 聊天壳白卡 1240 居中 + messages 模块灰底（2026-10-06 09:11 老大 prod 批注①②，协调人代改）
- 背景：18 轮批注④ v4 修法（`left:60 + right:0 + margin:0`）让壳白卡左起 60px 全宽铺，`max-width:1240` 失效，整块主区变白 → 老大批注①「背景不是白的」+ 批注②「得缩小点」
- 改法（行级，照抄；协调人 09:2x 代改，探针两轮校准后定稿）：
  1. `.sb2-chat-shell` `margin: 0 → margin: 0 auto`（left+right 双锚 + auto margin 自由空间均分 = 水平居中；**禁用 transform translateX**，18 轮 v3 层叠事故教训）
  2. `.sb2-chat-shell` `left: 60px → 0`（18 轮 v4 遗留锚点；探针实测 .sb2-side fixed 60..296、.app-main 起于 296，left:60 无对象可让、只制造 71/11 不对称灰缝；改后 (1322−1240)/2 = 41px 双侧对称）
  3. 新增 `.app-main:has(> #sb2ChatMain:not([hidden])) { background: var(--sb2-bg) }`（**messages-active 类不存在**——switchModule chat 分支提前 return 不打类，探针实测；故用纯 CSS :has 钩子，零 JS 改动；其他模块白底不动）
- 不动：壳 top 38 / bottom 18 / r14 / 白卡背景（18 轮批注④验收保持）；`[hidden]` 规则
- 验收：探针实测壳 rect（卡宽 ≤1240、水平居中、顶 y86 底缝 18）+ `.app-main` computed 背景 #F6F6F8 + 其他模块背景仍白

### 批注③-1 消息 tags（注入/召回/命中）
- **前置探查（必须先做）**：查后端 AI 回复是否把 MS3 记忆注入条数 / 知识召回条数 / 规律命中条数透传到消息 API（grep `solobrave-server.py` MS3 注入链路的响应字段）
- 有透传 → 前端在 assistant 气泡上方渲染三色 pill（样式照原型 tag：3px 8px / r999 / 11px，三色用现有 token）
- 无透传 → **只丢不造**：报数据缺口回来，不编数字，本项转「后端透传」待立项
- 验收：有数据时探针可见 tag；无数据时报告缺口说明

### 批注③-2 附件渲染 bug
- 现象：历史消息附件 `<img src="[object Object]">` ×4（附件对象没取 url 字段）
- 改法：修渲染处取附件 URL 的逻辑（先查 DB 里附件存的是什么结构，对症取字段）
- 验收：历史带附件消息图片 src 为合法 URL / base64，不再 `[object Object]`

## 第 13 条详解：中继端点模式（老大 2026-10-07 01:53 拍板立项）

**场景**：server 端某端点是 AI 专属（仅 `X-Agent-Id` 可调，真人 token 403），但前端要替真人用户触发这个动作。

**铁律**：**不做鉴权放宽，新建中继端点**。

- 原端点（如 `POST /api/proposals`，仅 AI 员工）保持 AI 专属语义不动 —— 放宽会让真人绕过 AI 审计链，破坏「AI 员工是行为主体」的记账语义。
- 新端点（precedent：`POST /api/collaboration-propose`）：
  - 真人 token 鉴权（admin/employee 都能调）；
  - server 端代理执行，以系统身份走原 AI 链路（如 round-robin 指派商务 Helen↔木木）；
  - **幂等去重**：按业务唯一维度（达人+商品）去重，重复提交返回已存在单据；
  - **前置拦截**：不满足前置条件（如已有 pending 单）直接 4xx 返回原因，不静默吞错。
- 前端 403 兜底不静默吞错（toast 显式提示「鉴权受限」）。

**反例**：直接给 `/api/proposals` 加 admin 白名单 → 真人绕过 AI 指派逻辑，幂等/拦截全失效，审计链断裂。

**apply when**：新端点鉴权设计；前端遇到 AI 专属端点 403；「真人触发 AI 动作」类需求评审。

**Precedent**：r39-7 智能派单中继（老大拍板 B，协调人代改 server 端点 + 前端接线；审批中心留真实单「大丸子 × 美印兔兔照片书」供体验）。规则由妍妍候选、老大拍板立第 13 条。

## 第 14 条详解：内联 JS 外置 + 内容 sha256 缓存钉扎（老大 2026-10-07 11:36 拍板立项）

**场景**：单体 HTML 膨胀到数万行（JS 占大头），多人多分支高频改同一文件，冲突和覆盖风险集中爆发。

**铁律**：**机械式外置，内容零改动，hash 钉扎缓存**。

- 按内联块出现顺序外置 `js/inline-NN.js`（序号映射原块，注释头标注来源），**内容零改动 + 顺序不变 + 全局作用域等价** — 不借外置顺手"优化"，不引 ES modules（会改变跨块作用域交互）。
- 原位换 `<script src="js/inline-NN.js?v=<内容 sha256 前 10 位>">`，hash 做缓存钉扎：内容变更强制刷新，不动 hash 浏览器可安全长缓存。
- **冲突面分散**：N 个外置文件 vs 1 个巨型内联，多人分支并行改不同块不再互踩。
- **改 JS 不再改主 HTML**：写码前 `ls js/inline-*.js` 看结构 + grep 函数名定位到对应文件再改；主 HTML 只剩 HTML/CSS。

**反例**：① 外置时顺手重构某块"顺便优化" → 内容不再可证等价，出问题无法二分定位；② 外置不带 hash → 上线后浏览器吃旧缓存，"改了没生效"玄学；③ 借外置改 ES modules → 跨块隐式全局交互全断，表面语法过、运行期炸。

**apply when**：单体 HTML > 2 万行且 JS 占比过半；多人多分支并行改同一 HTML；前端缓存"改了没生效"投诉。

**Precedent**：r39-20 ⑥ index.html 体积治理（老大 10:43 批准、10:51 开工；50555→17809 行，13 块外置，响应体积 -66%，side-restore + prod 双端 0 pageerror 验证）。规则由妍妍候选、老大拍板立第 14 条。

## 0. 定位与决策卡

| 卡问 | 答 |
|---|---|
| ① 服务「训练 AI」吗？ | **是**——它直接服务大脑的数据质量（kb_entries 是 RAG/记忆的底层） |
| ② 服务「选达人」吗？ | 否 |
| ③ 客户可见吗？ | 否——全部内部产出 |

结论：**值得上岗**，但循环要按「数据质量」设计，不是按「整理」设计。

## 1. 它到底守什么

知识库的真表 = `kb_entries`（不是 knowledge_base，§14 订正过）。入库分两档（L0 问答对 / L1 沉淀条目），
有 embedding（智谱语义包）。现在的入库审核在跑，但**没有任何人对「存量质量」负责**：
- 新增条目有人审（入库闸），存量 800+ 条没人复核
- 过期标记没人做（知识有时效：平台规则、佣金政策、类目趋势）
- 冲突条目没人对账（同主题多版本，哪条最新有效没人知道）
- embedding 缺失/陈旧没人补（backfill 是手工触发的）

## 2. 每日循环（草案，三选一或组合）

| 循环 | 扫什么 | 报什么 | 什么算异常 |
|---|---|---|---|
| **A 新增质检**（必选） | 24h 内新入库条目 | 抽检 N 条：字段完整/L0 有答/来源标注/无内部词 | 抽检不合格率 >20% 即报人 |
| **B 过期复核**（必选） | 全库按时效分桶 | 「疑似过期」清单：>90 天未验证 + 涉时效词（佣金/规则/活动） | 单桶疑似过期 >30 条报人 |
| **C 冲突对账**（候选） | 同主题多版本条目 | 冲突对清单（主题/条数/最新更新时间） | 同一主题 ≥3 个版本即报人 |

**建议先 A+B**（C 等冲突真出现时再加，避免为不存在的问题造循环）。

频率：**每 2 天一次**（知识库变化慢，日报太重；先从 48h 循环起步，量上来再加密）。
交付：notif 给管理员，格式对齐两管家（清单 + 数字 + 建议人工过目），
**「建议人工过目」同样不许写死「无」**。

## 3. 边界（boundary，防越界）

- **不判断哪条知识对**——价值/真伪裁决是人的（规格原话）
- 不删任何条目——只打「疑似过期/冲突」标记，删除决策归人
- 不改条目内容——只补字段/来源标注/embedding
- 不直接服务达人问答链路——它的产出是人看的清单，不进自动回复

## 4. 触发方式（上岗时定）

- 主动型（launchd 48h 循环）：照两管家范式，排班避开 9:30/10:47/11:17
- 或被动型（@驱动）：人在群里 @ 它才跑——**建议先被动**，跑顺了再排班

## 5. 验收口径（上岗定义）

1. 连续 3 次循环，每次都有真清单产出（抽检能命中真问题，不是空转）
2. 探针在岗名单恢复它（duty_status 回 ''），四层全 ✅
3. 老大在群里 @ 它问「知识库现在最脏的是哪块」，它答得出有证据的答案

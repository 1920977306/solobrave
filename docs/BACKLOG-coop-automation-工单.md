## 目标

样板库「合作机会」表（`DEMO_BASE=MZEdbVJMeah4x9sYYzncuhnbnnb` / `COOP_TABLE=tblolFFeJTNfyInn`）里有新的品牌合作机会、或机会状态发生变化时，**主动**把匹配的机会推给合适的达人——不等达人来问。这是"触达层"的核心增量，7188 网页不做（三层分工见 DAREN-ARCHITECTURE.md）。

## 触发条件（草稿，认领时可细化）

满足任一即触发评估：

1. **新增记录**：合作机会表出现新记录（品牌提交合作意向 → 运营录入/表单自动落表）
2. **状态流转**：记录状态变为「有意向」或「已合作」（运营在 7188 运营页改状态时写回的就是这张表，见 `coop_set_status`）

## 处理流程

```
触发 → 读记录（商品名/类目/佣金率/状态/预算）
     → 匹配达人：复用现有 match 引擎（talents × products 的 product_talent_match），
       筛出匹配分最高的 1-3 位已绑定达人（bind_douyin_id 非空）
     → 每位达人推一张飞书卡片：商品名 / 类目 / 佣金率 / 为什么适合你（一句人话）
       + 「查看我的工作台」专属链接（格式见下）
     → 落去重标记，防重复推送
```

## 硬要求

1. **防打扰**：同一达人每周至多推 2 条合作机会；同一条记录对同一人只推一次（用 record_id + tenant_key 去重，落 `bot_collect_tasks.payload` 或独立表）
2. **灰度铁律**：上线默认只推 `daren_boss` + `daren_test2`，跑满一个完整周期无误再放真达人（参照 WEEKLY-REPORT-DESIGN.md 的灰度教训）
3. **推送走 daren_bot Sender**：`db.get_latest_chat_id(tenant_key)` + venv python 那套成熟路径，别新造轮子
4. **lark 读写都用 `--as user`**，读表复用现有 lark_records 模式（120s 缓存）

## 验收

- 新增/改状态一条测试记录 → 对应达人收到卡片 → 重复触发不重复推 → 非灰度达人收不到
- 推送卡片里的达人链接点开能看到自己的驾驶舱（带 k）

## 本期不做

- 达人侧"接受/拒绝"回写（需 submit 事件，二期）
- 品牌方视角的通知（品牌走招商填表 + 运营人工，不自动打扰）

# 达人工作台对照分析：千问办公「多人工作台」 vs 我们的达人看板

日期：2026-10-19
起因：老大转发小红书视频（作者"一坨菜宝"，1199赞/706收藏），演示千问办公多人工作台之「达人投放工作台」场景。

## 一、对方是什么

千问办公 2026-09-07 上线「多人工作台」（量子位称"业内首个"）：
- 自然语言描述"有哪些角色、各自做什么、存什么数据"→ 生成可在线发布的协作应用
- 带角色权限、云端数据库、管理后台，最多百人同时在线
- 官方主打样板即「达人投放工作台」：品牌方同时管理多位达人和供应商——管达人名单、审核内容、跟进发布进度
- skill 可上传公开市场，他人一键安装复刻

来源：量子位 2026-09-07、极客公园 2026-09-09、阿里云千问办公产品页

## 二、功能对照表

| 维度 | 千问办公达人投放工作台 | 我们的达人看板（飞书应用模式） |
|---|---|---|
| 视角 | 品牌方/商家（管多个达人） | 达人本人（自助经营） |
| 协作 | 多角色（品牌/达人/供应商）同时在线干活 | 目前单人（运营可后台看） |
| 数据 | 人工录入/导入 | **百应自动采集 + 周报复盘 + AI 诊断（独有）** |
| 交付 | 免部署网页应用 | 飞书应用（多页面+导航）+ 聊天卡片长图 |
| 内容审核/进度 | 有（审核、发布进度跟踪） | 未做 |
| 复制推广 | skill 市场一键安装 | 模板复制（空间+应用+三表） |
| 权限 | 生成时角色权限 | 高级权限+千人千面仪表盘（已全量，未配置） |

## 三、最值得抄的三个协作功能（按落地难度排序）

### ① 合作意向入口（🟢 最易，1 周内）
招商/品牌通过一个**多维表格表单**提交合作需求（类目、预算、佣金、联系方式），提交后自动出现在达人看板的「合作机会」列表。
- 飞书原生：表单视图 + 自动化通知，零开发
- 我们已有同款数据管道（商品推荐记录表的模式直接复用）

### ② 带货进度看板（🟡 中，2-3 周）
选品→寄样→排期→开播→结算 五阶段，用画册/看板视图呈现，达人和运营共享同一张表、各改各的状态。
- 多维表格看板视图原生支持；状态变更可用工作流自动推飞书消息
- 给招商看进度 = "多人同时开工"的体感来源

### ③ 千人千面权限（🟡 中，随②一起做）
同一个看板：达人只看自己的数据，运营/管理员看全部。
- 高级权限+千人千面仪表盘已全量，缺的是配置（不是开发）
- 这也是对标千问"角色权限"的最直接 answer

## 四、路线建议（不切换技术栈）

1. **守住差异**：我们的护城河是"数据自动采集+AI 主动分析"，千问办公是"通用应用生成"，两者不冲突；达人视角 vs 品牌视角也不冲突。
2. **分阶段加协作**：先上①合作意向入口（本周就能做），跑通了再评估②③——②③一起做才是完整的"多人工作台"，但对内测 6 个达人来说现在做略早。
3. **展示层继续按第三方玩家风格打磨**（当前 v3 路线不变）：网页应用那种"产品感"，我们在飞书内用应用模式+长图卡片逼近，够用且零运维。
4. **观察项**：千问办公 skill 市场里达人工作台的实际装机量和口碑——如果社区生态起来很快，再考虑把我们的模板也做成"可一键安装"的形态（我们的模板本来就是要做成可复制导出的）。

## 五、风险/注意事项

- 千问办公背后是阿里电商数据源（1688/天猫/淘宝接入），长期看它做"选品+达人撮合"有数据优势；我们的百应采集要坚持周频稳定+周报粘性，用"陪伴感"对冲它的"工具感"。
- 飞书多维表格单表行数与协作规模上限远低于"百人同时在线"的网页应用——如果未来真出现"一个品牌管 50 个达人"的大客户场景，再考虑独立网页方案（FastMoss 式嵌入或自研）。
